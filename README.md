# 方舟食境 · ARK / TASTE

影石赛道一原型：把全景影像变成可浏览、可理解、可行动的美食空间。

## 运行

需要 Node.js 22.12+（当前环境 22.22.1）。

```sh
npm ci
npm run dev
```

打开终端打印的 Local 地址；端口被占用时 Vite 自动选择下一个。相机功能需另一个终端：

```sh
npm run bridge
```

电脑连接影石相机 Wi-Fi 后，在“影像工作台”点“检测影石相机”。相机上先选择普通全景录像模式并核对 8K30 与曝光。桥接仅绑定 127.0.0.1，前端经 Vite `/api` 代理访问。发布版提供浏览与本地资产查看；相机控制需要本地开发版，网站不会自动连接用户的局域网设备。

## 项目文件

- `src/scene.js`：参考建筑、餐厅示例、相机、资产查看。
- `src/data.js`：场所、示例菜品、通道图与来源。
- `src/routing.js`：图上的 Dijkstra 与最多四餐台的全排列路线优化。
- `bridge/osc.mjs`：官方 OSC 协议适配器。
- `bridge/server.mjs`：本地 HTTP 桥接。
- `docs/现场协作与拍摄清单.md`：明天实际怎么拍、怎么交接。
- `docs/SDK与重建接入方案.md`：SDK、算法、前端各自职责与可落地接入步骤。
- `docs/场地研究与建模依据.md`：来源、证据等级、未知项。
- `docs/产品与演示方案.md`：痛点假设、AI 闭环、验证与比赛演示。

## 验证

```sh
npm test
npm run build
```

测试覆盖路线连通性、重复餐台、未知/断开点位、OSC 串行与异步轮询、设备错误、录像模式检查、桥接跨站限制和并发拒绝。生产包中的 Spark 约 2.5 MB（压缩前），只在导入高斯文件时加载；大文件仍需裁剪或压缩，当前单文件上限为 300 MB，不代表手机均能流畅处理。

## 资料与精度

本项目使用本地两份赛事文档，并核对官方开发者资料。`../research-references/` 保留三张研究参考图与来源，未复制到网站发布目录。图像未发现开放转载许可，仅作内部研究参考。

模型是依据公开证据制作的研究原型，不是测绘数字孪生；无竣工图、真实室内采集和定标，不能承诺实际尺寸、路线长度或餐台位置。全景查看不等于六自由度 3D 重建，SDK 也不等于 3DGS 训练器。
