# 开图云部署与体系架构

## 本版可以部署什么

这是一个适合黑客松团队的单机架构：同源网页/API + SQLite WAL + 持久化素材目录 + 独立 CPU worker。无需购买 GPU 即可演示采集流程、素材上传、队列处理、全景/高斯浏览与清单导出。

- `app`：Node HTTP API，同时提供 Vite 生产网页；非 root。
- `worker`：安装 FFmpeg，领取素材检查 / ERP 抽帧任务；非 root。
- `kaitu-data`：SQLite、资产、处理中间文件，共享 Docker 本地数据卷。
- `caddy`：可选 HTTPS 入口；证书和配置有独立卷。
- 现场采集端：OSC / Camera SDK，靠近物理相机运行。
- GPU 处理：外部流程；当前不启动虚拟的“自动重建”任务。

SQLite 适合当前单服务器共享本地磁盘，不要放在 NFS 上，也不要把这份 Compose 当作跨主机集群。扩展多租户时再迁移 PostgreSQL、对象存储、队列及登录授权。

## 1. Linux 服务器

准备 Docker Engine 和 Compose 插件、Git，以及 Node.js（仅初始化配置时使用）。建议从 2–4 核 / 4 GB 内存、足够素材磁盘开始实测；这只是部署起点，不是并发性能承诺。8K 素材可能占用数十 GB。

```sh
git clone https://github.com/1739467001-svg/KaiTu.git
cd KaiTu
node scripts/init-env.mjs
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8080/api/health
```

初始化会生成权限为 0600 的 `.env` 和随机访问密钥，不覆盖已有文件。先通过 SSH 隧道访问：

```sh
ssh -L 8080:127.0.0.1:8080 user@your-server
```

本机打开 `http://127.0.0.1:8080`。在工作台连接服务时填入服务器 `.env` 中的 `KAITU_API_TOKEN`。这个密钥拥有该部署中所有场地的访问权，只适合团队共用的 MVP。

## 2. 域名与 HTTPS

域名 A/AAAA 记录先指向服务器；配置 `.env`：

```dotenv
KAITU_DOMAIN=your-real-domain.example
```

将示例域名替换为自己的实际域名。服务器放行 80/443，保留 SSH 管理入口，然后：

```sh
docker compose --profile https up -d --build
```

Caddy 自动处理证书。应用的 8080 端口仍只绑定本机，无需公开它。默认 Caddy 保留 Host，同源校验可正常通过；换用其他代理时也需转发原始 Host。

## 3. 实际操作与验收

1. 网页进入“影像工作台 → 导入 → 连接素材与任务服务”。
2. 输入访问密钥，点击连接，新建“仙林 · 第一段采集”。
3. 选择文件，点击上传；文件会写入数据卷，页面刷新后仍可从场地列表取回。
4. “处理”中点击“检查”；每约 1.5 秒 worker 领取一项任务，点击刷新查看结果。
5. 已拼接的 2:1 MP4 可“ERP 抽帧”：每 2 秒取一帧，最多 60 帧，导出 2048×1024 JPEG。小样流程有意限量，完整训练应另设高质量参数。
6. INSV / INSP 检查会显示“需外部处理”，提示先拼接。上传不能代替正确配对与完整分段。
7. 选择生成的 JPEG 点击预览；导入自己重建的 PLY / SPZ 后可独立浏览。
8. “交付”导出云端清单；本机锚点笔记另随采集清单导出，当前不自动云同步笔记。

```sh
docker compose logs --tail=100 app worker
```

访问密钥不写入前端 bundle、不放 localStorage、不写日志。清单与公开参考页面可在无密钥时浏览；私有素材、场地和任务接口需要密钥。此版没有用户注册、权限细分、审计日志或断点续传，公开大规模产品需另行补齐。

## 4. 数据与更新

`/data/kaitu.sqlite` 存储项目、检查项、素材元数据、处理任务。素材通过 UUID 命名，与原文件名分离，保留 SHA-256。数据库 WAL 支持一个 API 和 worker 使用同一本地卷。正在处理超过 10 分钟的任务会记为失败，需人工重提；不静默重做拍摄命令。

备份同时包含数据库和原始资产。推荐停服务后备份整个卷，避免只拷贝 SQLite 主文件漏掉 WAL：

```sh
mkdir -p backups
docker compose stop app worker
docker compose run --rm --no-deps -u root -v "$PWD/backups:/backup" app tar -czf /backup/kaitu-data.tgz -C /data .
docker compose up -d app worker
```

备份文件应离机保存并演练恢复。`docker compose down` 保留数据卷；不要添加 `-v`，那会删除素材库。更新代码：

```sh
git pull --ff-only
docker compose up -d --build
```

使用 HTTPS 的部署在最后一条加 `--profile https`（即 `docker compose --profile https up -d --build`）。当前没有数据库迁移版本框架，后续改表结构须先备份、补迁移再发布。

## 5. SDK 与 GPU 扩展位置

- Camera SDK 放现场设备代理中，以既有 `/api/camera/*` 形状对接 UI；云端只接收文件/状态，不直接找 `192.168.42.1`。
- Media SDK 放官方支持的 Windows/Linux/移动端环境中。桌面 Media SDK 的 GPU 和授权按赛方包执行。不能在这个通用 CPU worker 中假定有 SDK。
- 重建服务接收拼接后的影像、真实相机模型/位姿与锚点，输出模型、统计与变换。推荐先人工离线跑通小样，再加新任务类型、权限和回调签名。
- AI 语义应输出附原图依据的候选点位，经人工确认后才成为空间服务数据；API key 放后端。

## HTTP 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 无鉴权健康状态与能力 |
| GET / POST | `/api/projects` | 列出 / 创建场地 |
| GET | `/api/projects/:id` | 素材与任务快照 |
| PUT | `/api/projects/:id/checklist` | 布尔检查项 |
| POST | `/api/projects/:id/assets?name=...` | 原始二进制上传 |
| GET | `/api/assets/:id` | 鉴权下载 |
| POST | `/api/projects/:id/jobs` | `{assetId,kind:"inspect"或"extract"}` |
| GET | `/api/projects/:id/manifest` | 资产、状态、待配准清单 |

除 health 外，上述接口要求 `Authorization: Bearer <访问密钥>`。用户上传素材未发布为公开静态资源；不要把原始影像放到 Vite 的 public 目录。

## v0.3 三场景与 AI / 商业演示

`src/venues.js` 是三个场地、服务点位、7 套餐与 9 行程的共享目录。Node AI 适配器和浏览器读取同一份数据，Docker runtime 显式复制它，避免只部署 dist 后目录缺失。

可选环境变量：`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`。接口 `/api/assistant` 沿用团队访问密钥与同源校验，两路并发、25 秒超时，返回当前目录中的方案 ID。禁止将模型密钥写入 `VITE_*` 或发布到前端。

目前的领券、核销和看板是浏览器 localStorage 沙盘，带示例底稿与本次操作区分。它不跨设备同步，也不是支付/券生产账本。生产扩展应在 API 层增加场地/商户账户、租户隔离、持久化券、有效期/撤销、原子核销与审计，再接真实商户服务。当前部署保留单团队原型边界。

静态 Sites 链接只承载前端演示：三场景、本地意图、合成全景与本机商业沙盘。实时 AI、上传和 CPU worker 使用这里的 Docker/Node 云服务器架构。
