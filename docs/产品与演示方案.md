# 开图 · Unfold：产品与演示方案

保留用户已确定的名称 **开图**。Unfold 表达空间逐步展开，与“走一圈，让场地成为可调用的空间”一致。更换为食品主题名称会把工具误解为单一餐饮应用。

## 核心用户与价值

核心用户是需要让新场地接入空间服务的运营者、活动组织者和采集团队。影像工作台是竞争力：降低“怎么拍、拍完怎么处理、哪里还缺资料、怎样交付”的门槛。3D 场地是结果和展示窗口，取餐路线是可接入服务的样例。

从组队提案吸收三点：走一圈开图的低门槛入口、已有服务迁入新场地的方向、首个现场样本的端到端演示。没有把其他团队身份或联系方式写入此公开仓库，也不把提案中尚待验证的自动化能力当成事实。

## 最小可验收闭环

1. 现场拍 20 秒测试片，核对设备、清晰度、文件配对。
2. 完成一个主入口 / 公共区域的 3–5 分钟闭环。
3. 拼接为 ERP，上传素材，完成检查 / 抽帧；明确展示真实任务状态。
4. 导入全景或已完成的 3DGS，确认可浏览、方向正确。
5. 记录至少三个固定锚点与实测长度，说明尚未配准的部分。
6. 导出场地清单，现场复测一个具体任务。

“30 分钟上线”须定义：起点是按下录制还是已有影像；终点是可浏览还是已配准且可服务；GPU 等待是否计入。工作台记录采集起点和导出时经过分钟数，不宣传已达成 30 分钟全自动重建。

## 三分钟比赛演示

- 0:00–0:25：一个新场地接入服务，最费时的环节是什么；给出现场采访证据。
- 0:25–0:55：打开仙林参考模型、昼夜变化、水幕预演，解释这是首次场地与视觉入口。
- 0:55–1:50：进入核心工作台，展示真实拍摄小样、上传、真实处理结果、真实全景/高斯产物。
- 1:50–2:20：显示锚点和采集清单，区分视觉完成与可服务数据完成。
- 2:20–2:40：服务示例的点位与路线联动，解释未来如何迁入其他空间服务。
- 2:40–3:00：实际耗时、现场任务结果与下一步。

若 GPU 尚未完成，演示真实全景闭环并报告重建进展；不要将单张全景球面或参考建筑当成实拍 3DGS。“一句话调度”仍是后续需要 AI、可用工具接口和可核验路网的产品方向。

## 现场验证

先请 3–5 位活动组织者或场地运营者描述当前上架新场地的步骤、耗时、失败点与责任人，再让一位未参与开发的人按工作台完成小样交付。记录哪里需要额外讲解、失败重拍次数、有效操作分钟数和等待分钟数。

游客找餐测试可保留，但只能证明该服务样例的价值，不能替代对“场地接入工具”本身的验证。样本量有限时展示原始观察，不声称统计显著。
