# 明天的现场协作与拍摄清单

第一目标：先拿到“餐厅入口 → 2–3 个餐台 → 回到入口”的可重建小场景，再扩展园区。细节照片能补纹理和菜单信息，但仅靠零散照片通常不足以建立稳定的整个度假村 3DGS。

本清单依据项目根目录《3DGS拍摄指南.md》《影石赛事SDK与开源算法开发调用指南.md》。目前按有一台 X5、自拍杆、能导出原文件的电脑准备；实际设备、GPU 与截止时间待团队确认。

## 现场与线上分工

| 阶段 | 你们在线下 | 我在线上 / 项目中 | 验收点 |
|---|---|---|---|
| 首个 10 分钟 | 拍导览牌、餐厅入口、第一段 30–60 秒测试视频 | 检查清晰度、拼接、路径重叠、曝光与文件结构 | 能读清菜单，静态物体没有明显重影 |
| 接下来约 20–30 分钟 | 完成一个小餐饮区域闭环，补不同高度和遮挡角落 | 整理采集索引，拼接或接收 ERP，先跑小样重建 | 场景能连上，地面/餐台可辨识 |
| 内容补充 | 每个菜品拍实物、菜牌、位置关系，询问真实配方 | 建立菜品表、图像证据与空间锚点 | 3–5 个菜品信息经人工确认 |
| 精度校准 | 记录至少 3 个不共线固定点，测两段可复现长度 | 对齐模型位置/旋转/比例，替换示例通道图 | 路线不穿墙、不穿餐台 |
| 演示验证 | 让 5 位参与者完成相同找餐任务 | 记录耗时、误找、问询、满意度，修交互 | 有真实观察记录，而非猜测需求 |

按小批交接推进：不要等全场拍完才检查第一次数据。

## P0 必拍：先确保可交付

### XL-03：图纸与尺度，约 5–10 分钟

- 园区导览牌：正面一张完整图，再分区近拍文字。
- 餐厅所在楼层的平面图/疏散图：包含方向、门、楼梯、电梯、比例或尺寸。
- 拍清“你在这里”及其与入口的相对位置。
- 有条件向场地方索取电子总平、餐厅平面或 CAD/PDF；记录版本日期与可用范围。
- 用卷尺或激光测距测两段可复现的长度（如门宽、柱间距），照片里标清端点。相机高度和拍摄方向也记录。
- 不把手机 GPS 当成室内坐标精度来源；3DGS 本身也不自动给出真实米制尺度。

### XL-01：餐厅小场景，约 20 分钟采集

- 开拍前先清洁镜头。按赛事指南优先 8K30 全景、运动 HDR、固定参数；用现场样片确认具体机型的模式兼容性和运动模糊。若有冲突请由影石现场工程师确认可用组合，不要假设所有参数同时开放。
- 尽量在人员少、照明稳定时段拍。固定桌椅、菜盘与门的位置，拍摄期间保持一致。
- 使用平移而非站在原地旋转。沿外圈走一遍，再沿通道走井字；速度小于 1 m/s。
- 相邻视角约 70–80% 重叠；每段 3–5 分钟，结束回到起点附近形成闭环。
- 通常距目标 1–2 米，关键餐台由一侧镜头正对，尽量避开拼接缝。
- 在安全可达条件下补低、中、高不同高度，按指南约 1 米高度间隔；天花板、地面和遮挡角落单独补。无需危险举杆或影响现场通行。
- 跨房间时拍清门框和连接走廊，保证两侧共享足够静态纹理。
- 对玻璃、镜子、反光餐具与流动水面，拍清周围稳定结构；不要期待这些区域自动完美重建。

### XL-02：菜品与语义证据，约 10–15 分钟

每道优先菜品采集三种照片：

1. 菜牌正面近照，可读菜名、主要配料及现场标注。
2. 菜品实物斜俯视与另一侧照片；细节可用手机/单镜头，更利于识别。
3. 带相邻餐台或固定地标的环境照，用来把菜品放回空间。

记录：原文件名、拍摄时间、餐台名、现场确认人/来源、信息确认时间。真实配方和过敏原由工作人员确认；AI 只能提取和提示，不能从外观证明“无某种过敏原”。菜单每天可能变化，要保留时间版本。

## P1：建筑与园区补全

- 正门招牌、入口雨棚、转弯、楼栋连接处；每面立面补正视与左右斜视。
- 沿弧形客房楼缓慢平移，补不同高度；宽景展示完整体量，细景解释窗格和材质。
- 湖岸泳池、公共裙房、湖边路；同时记录真实的餐厅/U Bar 所在位置。
- 无人机仅在现场允许的条件下使用；不把无人机作为完成原型的前提。赛事指南针对建筑立面建议距离至少约 3 米、速度小于 3 m/s、多高度；大范围地面建议目标上方 10–20 米，均需服从现场边界和设备安全条件。
- 如用 A1 + X5，地面起始区和起飞区共享静态地标，确保空地素材有可匹配的重叠。

## 文件交接

保留原文件名和同一条录像的所有镜头/分段文件，不转发聊天软件压缩视频，不只给截图。

```text
captures/2026-09-23/
  XL-01-restaurant/original/     原始 INSV/INSP（全部配对与分段）
  XL-01-restaurant/erp/          拼接后的 2:1 JPG/MP4
  XL-02-menu/original/           菜牌 + 实物 + 环境照
  XL-03-plans/                   导览图、楼层图、实测记录
  XL-04-exterior/original/       建筑补充
  manifest.json                 文件与区域映射
```

网页“影像工作台”能下载 `xianlin-capture-manifest.json`。原始素材留在本地工作区，导入网页时目前不会上传。首次先交 XL-03 图纸、一个小样视频和三张菜单照片。

## 出发前向主办方取得

- 正式 SDK 压缩包、当前版本文档、支持的机型/固件及 sample；目前本地指南的 ZIP 链接均为 `#` 占位。
- 是否提供 GPU 工作站/重建服务，以及输出格式是否能导出 Gaussian PLY / SPZ。
- 场地可采集区域、餐厅低峰时段、是否可使用电子平面图。
- 相机与电脑连接方式、USB 安卓模式要求（赛事指南注明 5V3A）、高速存储卡和足够电量。

如果没有 GPU：优先保证官方工具导出的 ERP 全景可以展示、菜单与点位可以互动，再把一个小场景交给主办方的重建环境。不要用未经重建的全景球伪称真实 3DGS。
