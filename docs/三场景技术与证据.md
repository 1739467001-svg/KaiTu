## 已落地的成熟渲染方法

采用现有 Three.js 0.186.0 与 Spark 2.2.0，未为追求“最新”盲目替换已稳定的工具链。

- [MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html)：粗糙度、环境照明与程序化砖/瓦/铺地纹理；斜坡屋顶、瓦端、木窗格和石雕层次。
- [Water 官方示例](https://github.com/mrdoob/three.js/blob/dev/examples/webgl_shaders_ocean.html)：低分辨率平面反射和动态法线水纹。反射在法线覆盖渲染期间跳过，避免干扰环境遮蔽。
- [GTAOPass](https://threejs.org/docs/pages/GTAOPass.html)：可切换环境遮蔽，增强墙角、屋檐和建筑间的接触层次。
- [UnrealBloomPass](https://threejs.org/docs/pages/UnrealBloomPass.html)：夜间亮部辉光，与窗灯、灯笼、水幕配合；再经 OutputPass 色调映射与 FXAA。
- [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)：批量树冠、树干和瓦端；静态几何按材质合并，其他场景首次进入才构建。
- 动态游客与少量树叶风动提供生活尺度；偏好减少动画时停止游客步行。太阳位置仍为南京城市坐标近似，地理北向未校准。
- 全景示例由 CubeCamera 六面捕获转成 2:1 ERP；用 Three.js 球面浏览，同一份内容可取横版/竖版静态图。文件与页面均标记“合成样例，非实拍”。

## X4 Air 的明确作用

[官方产品页](https://www.insta360.com/cn/product/insta360-x4-air) 与 [官方发布信息](https://news.insta360.com/x4-air/)：165 g、8K30 全景、单镜头 4K60、先拍摄后取景。没有套用其他机型的专属功能。

1. 空间：全景 8K30，慢走平移、闭环重叠。先拍 20 秒验证曝光/拼接。导览先用清晰 ERP 照片也能落地，不需要等整个景区完成 3DGS。
2. 餐饮：单镜头视频/照片补店面、菜单与食品细节；菜品信息和价格仍由商家确认，不从图片猜过敏原。
3. 内容：全景一次采集，多方向再取景。本网页已实现静态取景器，完整高码率视频重构图交给 Studio/SDK 工作流。
4. 真实设备 → 官方拼接 → 导入全景 / 外部 GPU 重建 → 导入 Gaussian → 人工校准路网和服务点位。相机直连 OSC 有真实协议实现，但 X4 Air 仍需硬件联调；原生 SDK 二进制与授权尚待赛方提供。
